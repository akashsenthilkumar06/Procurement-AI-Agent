# Ozer Game

This case implements the Human–AI Forecast Information Sharing Game from the supplied Ozer Game guide. The versioned pack holds the protocol constants. Existing case studies continue to use their own workflows.

In **Agent setup → Generate with AI**, attach a text-based PDF, DOCX, TXT, or Markdown protocol. Setup chat needs a server OpenAI key. For a matching Ozer protocol it drafts a name, research description, and separate goals and instructions for the two AI counterparts. **Save draft & edit** creates a new saved preset. The installed Ozer case supplies the rounds, workflow, decision bounds, and payoffs; an upload does not rewrite those rules. Review the proposed changes and any notes about mismatches or defaults.

You can also start without an upload: **New setup → Design → Participant task → Replace with a case template → Ozer Game · Forecast information sharing**. **Test this setup** opens either human role. The default preview is deterministic and keyless: the retailer reports X and the supplier produces the reported quantity, within the decision bounds. To test the saved counterpart goal and instructions, select **OpenAI** in **Study controls**, save, and turn on **Use live OpenAI for this preview** in the role picker. That preview uses the saved model and API budget and is marked as a preview in the study data.

For actual enrollment, keep the configured OpenAI model and server key, set **Participant enrollment** to **Active**, save, and select **Use for study**. Both roles use the configured model snapshot and fixed temperature. Random role assignment is the default and the role is fixed for the session.

Consent precedes instructions, the role screen, and a three-question comprehension check. Incorrect answers can be retried. Each round gives the participant 60 seconds from the server opening the decision stage. A timeout ends the session and records the incomplete round without a synthetic decision or payoff. The participant gets a return-to-survey message and the researcher sees a flag. Once both actions lock, the server samples the shock and calculates demand, sales, and both profits. The three practice rounds have a separate running total and are excluded from final pay. The server records completion when round 23 settles. The participant can still reopen final-round feedback and continue to the results screen.

The decision bounds are whole numbers from 0 to 475 for both the report and production. This permits over-reporting above the maximum private signal and covers the maximum possible demand. The model receives the public game rules and the saved goal and instructions for its own role, plus X for the retailer or F for the supplier. It receives no chat, tools, or prior-round context. Setup validation checks that the input allowance can fit the role guidance before starting a live session. The supplier never receives X as a separate field. The authorized forecast report can equal X. The participant sees their own profit and role-appropriate information. The researcher can audit both players’ decisions, private draws, timings, and payoffs in Session review and the decision/event exports.

The results screen calculates the guide’s $5 participation payment plus a performance bonus at 50,000 experimental dollars per USD. A negative paid profit yields a zero bonus, preserving the participation amount. The app calculates the amount and shows a completion code for returning to the survey. The researcher handles disbursement and any compensation for incomplete sessions.

Run the Ozer tests with `.venv/bin/python -m unittest discover -s tests -p test_ozer.py -v`. They exercise PDF extraction through the setup chat, saving and reopening a generated preset, the keyless and live-preview paths, both roles through all 23 rounds, and recorded payoffs, information boundaries, duplicate submissions, and expiration. The provider is simulated in these tests.
