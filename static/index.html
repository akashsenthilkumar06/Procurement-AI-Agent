    Prompts and responses

    Choose how to guide the model. Few-shot uses the example conversations below. Public rationale asks for a short explanation the participant can see.
    Choose whether the response should be a recommendation, an explanation, or a number. Some case or authority settings impose their own format.
    Use Standard for ordinary advice. Flawed is an experimental condition intended to make the advice worse.
    Example conversations

    A JSON array with “user” and “assistant” strings, used in few-shot mode.

    Private data

    Private data stays outside the conversational model. These conditions use controlled responses.

    Set the supplier’s minimum or buyer’s maximum acceptable price. These negotiation-only limits stay on the server and are enforced by the offer policy. Clear them before changing this condition to supplier selection. With no private bounds, any price inside the public range is eligible.

    Use this for private condition values, not participant-facing instructions. For negotiation price limits, use the price fields above when available.
    Eligibility rules

    Numeric min/max bounds affect the agent’s choice. Other private information is stored for the researcher only.

    Model & study controls

    Settings shared by every group: model, memory, enrollment, consent, and data collection.

    Demo uses built-in responses and needs no key. OpenAI uses the model and budget settings below.

    Use an exact dated model ID for API studies so a model alias cannot change the model during the study.
    Choose whether the model sees earlier messages from this participant’s session. Messages never carry over to another participant.

    Ozer uses only the current round’s information.

    Model controls and spending limits
    Controls how much responses can vary on models that support it. Lower values tend to make responses more consistent.
    Choose how much reasoning the model should use when the selected model supports this setting.

    This model doesn’t support a reasoning effort setting.

    The app stops admitting new API sessions when it cannot reserve their allowance within this cap.
    The app sets this amount aside when an API session starts so it can finish within its own budget.

    Token limits & cost accounting

    The application reserves a request’s maximum configured cost before calling the API. Unknown or failed usage retains that reservation. Prices are accounting inputs; verify them when changing models. This is separate from provider billing limits.
